Bluetooth Provisioning Flow
ⓘ WiFi credentials (SSID/Password) and the User Secret are transmitted over Bluetooth (BLE) during initial setup. No HTTP auth API is used for provisioning. Once the controller joins WiFi, the User Secret becomes the permanent authentication key for all API calls.

Discovery
ⓘ Most endpoints require the Authorization: Bearer <user-secret> header. Look for the 🔒Auth badge on individual cards. The User Secret is the permanent key assigned during BLE provisioning.
GET /api/ping Unauthenticated ping — is controller alive? ▶
Called immediately after mDNS discovery. No auth header. Returns only basic identity — no sensitive WiFi or config data.
Request
GET /api/ping // No Authorization header needed
Responses
// 200 OK { "ok": true, "deviceId": "DMX-CTRL-A4F2", "firmwareVersion": "2.1.0", "uptimeSeconds": 3600 } // 503 Busy { "ok": false, "error": "controller_busy" }
GET /api/ping/details Authenticated ping — full status including WiFi details 🔒Auth ▶
Requires the User Secret in the Authorization header. Returns full controller status including current WiFi network details. Use this as a heartbeat to verify connection is still alive.
Request
GET /api/ping/details Authorization: Bearer <user-secret>
Responses
// 200 OK { "ok": true, "deviceId": "DMX-CTRL-A4F2", "controllerName": "Stage Left", "firmwareVersion": "2.1.0", "uptimeSeconds": 7200, "wifi": { "ssid": "VenueWiFi_5G", "ip": "192.168.1.42", "signal": -58, "connected": true } } // 401 Secret invalid / incorrect { "error": "unauthorized" }
2
Network & System
PUT /api/network/wifi Update WiFi SSID and password ▶
Used when the venue WiFi changes. Updates SSID/Password only; the User Secret cannot be changed via this API. The controller reconnects immediately, dropping the current session.
Request payload
{ "ssid": "NewVenueWiFi_5G", "password": "newp@ssword", "securityType": "WPA3" } // securityType: "WPA2"|"WPA3"|"WEP"|"OPEN"
Responses
// 200 OK — connecting to new network { "ok": true, "status": "reconnecting", "message": "Session will drop. Reconnect after join." } // 401 Wrong secret { "error": "invalid_secret" } // 400 Bad payload { "error": "invalid_payload", "message": "ssid is required" }
POST /api/network/reset Clear WiFi credentials — triggers BLE provisioning mode 🔒Auth ▶
Clears stored WiFi credentials only. All device, group, scene, and effect data is preserved. Controller immediately enters BLE provisioning mode. Use this when moving the controller to a completely different network.
Request
POST /api/network/reset Authorization: Bearer <user-secret> // No body required
Responses
// 200 OK { "ok": true, "status": "ble_provisioning_mode", "message": "WiFi cleared. Use BLE to re-provision." }
POST /api/system/factory-reset Full factory reset — wipes everything 🔒Auth ▶
⚠ Destructive — permanently deletes all devices, groups, scenes, effects, and WiFi credentials. Controller reboots into BLE provisioning mode. Cannot be undone.
Request
POST /api/system/factory-reset Authorization: Bearer <user-secret> // No body required
Responses
// 200 OK { "ok": true, "status": "factory_reset_complete", "message": "All data wiped. BLE provisioning mode active." }

Configuration
GET /api/config Full controller state — called once on every connect 🔒Auth ▶
App caches in memory only — controller is the sole persistent store. No model definitions here; those are app-side.
Response 200
{ "controllerId": "DMX-CTRL-A4F2", "controllerName": "Stage Left", "devices": [ { "id": "d1", "name": "Spot 1", "uid": "06AE:00000001", "modelId": "m26", // app resolves this to channel map "dmxAddress": 1, "channelCount": 8 } ], "groups": [ { "id": "g1", "name": "Stage Left", "deviceIds": ["d1", "d2"] } ], "scenes": [ { "id": "sc1", "name": "Warm Welcome", "targets": [ { "type": "device", "id": "d1", "values": { "dimmer": 255, "red": 200 } }, { "type": "group", "id": "g1", "values": { "dimmer": 150 } } ] } ], "effects": [ { "id": "ef1", "name": "Pulse", "loop": true, "steps": [ { "sceneId": "sc1", "duration": 2000, "fade": 500 } ] } ] }

Device (Fixture) Management
GET /api/devices List all configured fixtures 🔒Auth ▶
// 200 OK [ { "id": "d1", "name": "Spot 1", "uid": "06AE:00000001", "modelId": "m26", "dmxAddress": 1, "channelCount": 8 }, { "id": "d2", "name": "Wash 1", "uid": null, "modelId": "m12", "dmxAddress": 9, "channelCount": 2 } ]
POST /api/devices Add a new fixture 🔒Auth ▶
The app resolves the modelId locally. uid is the hardware RDM identifier (if applicable). Controller uses channelCount to check for DMX address overlap.
Request payload
{ "name": "Spot 2", "uid": "06AE:00000002", "modelId": "m26", "dmxAddress": 9, "channelCount": 8 }
Responses
// 201 Created { "id": "d3", "name": "Spot 2", "uid": "06AE:00000002", "modelId": "m26", "dmxAddress": 9, "channelCount": 8 } // 400 Address conflict { "error": "dmx_address_conflict", "conflictingDeviceId": "d2", "conflictRange": [9, 16] }
PUT /api/devices/{id} Edit fixture name, address, model, or assignment 🔒Auth ▶
Request payload (all optional)
{ "name": "Spot 2 Renamed", "uid": "06AE:00000002", "modelId": "m27", "dmxAddress": 17, "channelCount": 8 }
Responses
// 200 OK { "id": "d3", "name": "Spot 2 Renamed", "uid": "06AE:00000002", "modelId": "m27", "dmxAddress": 17, "channelCount": 8 } // 404 { "error": "device_not_found" } // 400 Conflict { "error": "dmx_address_conflict" }
DELETE /api/devices/{id} Remove fixture from controller 🔒Auth ▶
// 200 OK { "ok": true, "deletedId": "d3" } // 404 { "error": "device_not_found" }

Real-time DMX Control — Raw mode only
POST /api/control Bulk control via device ID and relative channels 🔒Auth ▶
Send an array of device control objects. Channel numbering is relative to the fixture's DMX start address.
Request payload
[ { "deviceId": "d1", "channels": [ { "channel": 1, "value": 255 }, { "channel": 4, "value": 200 } ] } ]
Responses
// 200 OK { "ok": true, "appliedAt": "2026-05-12T10:30:00Z" }
POST /api/control/raw Direct global channel mapping (Key-Value) 🔒Auth ▶
Send a JSON object where keys are global DMX addresses (1–512) and values are 0–255. No device IDs needed.
Request payload
{ "10": 200, "11": 112, "20": 120, "21": 230 }
Responses
// 200 OK { "ok": true, "appliedAt": "2026-05-12T10:30:05Z" } // 400 Bad format { "error": "invalid_raw_mapping" }
